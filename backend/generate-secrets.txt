HOW TO GENERATE NEW SECRETS FOR backend/.env
==============================================

Run each command below inside the "backend" folder (bcryptjs is already
installed there). Copy the printed output and paste it as the value for
the matching line in .env.

------------------------------------------------------------
1) JWT_SECRET
------------------------------------------------------------
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

------------------------------------------------------------
2) ENCRYPTION_KEY
------------------------------------------------------------
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

------------------------------------------------------------
3) ADMIN_PASSKEY_HASH
------------------------------------------------------------
Replace "choose-a-passkey" with the real passkey you want admins to use,
then run:

node -e "console.log(require('bcryptjs').hashSync('choose-a-passkey', 10))"

The command prints a bcrypt hash starting with $2a$10$... — that hash is
what goes into ADMIN_PASSKEY_HASH in .env. The plaintext passkey itself
is never stored anywhere — write it down somewhere safe (e.g. a password
manager) and share it out-of-band with authorized admins only.

==============================================
IMPORTANT WARNING
==============================================
Your current tcc_1_final.zip already has WORKING values for all three,
matching your existing MySQL database and all student data you've
already encrypted/tested.

Only run these commands if you deliberately want to ROTATE to brand-new
secrets. If you do:

- Changing JWT_SECRET logs everyone out (existing tokens stop working) —
  harmless, they just log in again.
- Changing ENCRYPTION_KEY makes ALL previously-encrypted student data
  (date of birth, address, mobile, guardian contact) permanently
  undecryptable with the new key. You would need to re-enter that data
  after rotating this key.
- Changing ADMIN_PASSKEY_HASH just changes which passkey admins must
  enter to decrypt sensitive fields going forward — no data is affected.
